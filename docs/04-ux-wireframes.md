## ۲. معماری اطلاعات (Sitemap)

```
ورود (F1)
└── پنل مدیریت [نوار کنار: داشبورد · تقویم · کلاس‌ها · هنرجویان · اساتید · ترم‌ها · سازها و اتاق‌ها · تنظیمات]
    ├── داشبورد — جلسات امروز + کارهای معوق
    ├── تقویم هفتگی ⭐ — فیلتر اتاق/استاد، کلیک روی جلسه → مودال اقدامات
    │   └── مودال جلسه → ثبت حضور و غیاب | ویرایش این جلسه | لغو این جلسه (F4-AC7)
    ├── کلاس‌ها — لیست سری‌ها → فرم کلاس (تکرارشونده/جلسه‌ای + پیش‌نمایش جلسات + خطای تداخل)
    ├── جلسه ⭐ — جزئیات + ثبت حضور و غیاب (F5)
    ├── هنرجویان — لیست/جستجو → فرم هنرجو · پروفایل (داده مشتق‌شده)
    ├── اساتید — لیست → فرم استاد
    ├── ترم‌ها (F0) · سازها و اتاق‌ها · تنظیمات (ساعات کاری)
```

**قاعده ناوبری:** هر موجودیت ۳ نما دارد (لیست / فرم / جزئیات). «جلسه» تنها موجودیتی است که از تقویم و داشبورد قابل دسترسی است، نه از نوار کنار — چون همیشه در بسترِ یک روز دیده می‌شود.

## ۴. تصمیم‌های UX و دلیل آن‌ها

| # | تصمیم | دلیل |
|---|---|---|
| U1 | داشبورد «امروز-محور»: جلسات امروز + معوقات، نه آمار عمومی | ادمین تک‌نفره هر روز صبح همین را نیاز دارد؛ گزارش پیشرفته خارج از MVP است |
| U2 | خطای تداخل **قابل‌اقدام** است: نام کلاس متداخل + پیشنهاد جایگزین | F4-AC3/AC4 فقط «جلوگیری» نمی‌خواهند؛ تجربه بهتر = رفع سریع تداخل |
| U3 | **پیش‌نمایش جلسات** در فرم کلاس (تعداد + اولین/آخرین جلسه) قبل از ثبت | جلوگیری از «ثبت کورکورانه» سری ۱۴ جلسه‌ای؛ منطق F0-AC3 را برای کاربر شفاف می‌کند |
| U4 | نوع کلاس در تقویم با **الگوی کادر** کدگذاری شده (نه فقط رنگ) | در وایرفریم خاکستری ممکن بود؛ در پیاده‌سازی رنگ + آیکن (دسترس‌پذیری) |
| U5 | حضور و غیاب کارتی با ۳ دکمه (حاضر/غایب/موجه) + دکمه «همه حاضر» | ورود داده سریع سر کلاس؛ جدول در موبایل ناخواناست |
| U6 | جلسه لغوشده با خط‌خوردگی باقی می‌ماند (حذف نمی‌شود) | هم‌راستا با Soft Delete فاز ۳ — سابقه حذف فیزیکی ندارد |
| U7 | مقادیر مشتق‌شده (جلسات باقی‌مانده و…) با برچسب «محاسبه‌شده خودکار» | تا در پیاده‌سازی اشتباهاً فیلد ورودی دستی ساخته نشود (تصمیم D6) |
| U8 | جستجوی لیست هنرجویان: نام/تماس/کد ملی در یک فیلد | F2-AC5 — ادمین معمولاً فقط یک شناسه در ذهن دارد |
| U9 | ریسپانسیو: تقویم در موبایل اسکرول افقی + نوار کنار به منوی کشویی | تقویم هفتگی ذاتاً جدولی است؛ نمای لیستی کامل را به فاز پیاده‌سازی موکول کردیم |

## ۵. جریان‌های کلیدی برای تست (چک‌لیست بازبینی)

1. **جریان زمان‌بندی (مهم‌ترین):** تقویم → کلیک روی یک کلاس → مودال → «ثبت حضور و غیاب» — آیا مسیر طبیعی است؟
2. **جریان کلاس جدید:** فرم کلاس → سوییچ «جلسه‌به‌جلسه» (بخش برنامه هفتگی مخفی می‌شود) → خطای تداخل را بخوانید — آیا پیام کافی و قابل‌اقدام است؟
3. **جریان حضور و غیاب:** صفحه جلسه — کارت‌های ۴ هنرجو با وضعیت‌های مختلف + فیلد دلیل برای «موجه».
4. **جریان هنرجو:** لیست → فرم (خطای کد ملی تکراری) → پروفایل (داده مشتق‌شده و جای خالی MVP-2).
5. **ریسپانسیو:** پنجره مرورگر را باریک کنید — منو کشویی می‌شود، کارت‌ها تک‌ستونه می‌شوند.
